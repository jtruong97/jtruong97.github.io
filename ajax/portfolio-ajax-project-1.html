FullyBookd

Why I Built It:

I read a lot, and I kept running into the same problem. I'd finish the last published book in a series, hit a cliffhanger, and only then realize the series was unfinished — sometimes abandoned years earlier. I was tracking what I was reading in a notes app, which made it easy to lose the thread entirely and forget a series existed.

Before starting anything new I'd research whether it was complete, and the answer was often wrong. Goodreads didn't solve it. So I built FullyBookd: start only completed series, or follow an unfinished one and get told when the final book is actually out.

The app answers the question directly — it will tell you, for instance, that A Song of Ice and Fire is still ongoing, that the last book landed in 2012, and that nothing has been announced in the fourteen years since.

What's Interesting:

Built and shipped solo. The catalog has grown from 13,000 to roughly 14,900 titles.

Beyond series tracking, it handles the rest of a reading life: a release calendar, per-format ownership (physical, e-book, audiobook), page-level progress, reading streaks, and yearly goals. It runs as a web app and as a native iOS app built with React Native and Expo, both against the same Supabase backend.

  • Scheduled serverless pipelines (Supabase Edge Functions) discover new titles from followed authors and backfill missing metadata — bounded batches, oldest-first queue rotation, and a rate-limit circuit breaker so runs resume where they left off.
  • Metadata reconciled across three external APIs (Hardcover, Google Books, Open Library) with per-field fallback, validating candidate publication dates against an independently-sourced anchor year rather than taking last-write. A 0–100 quality score sets refresh cadence.
  • Local-first search queries the Postgres catalog through a fuzzy-match RPC before falling back to external APIs, with coverage-weighted relevance ranking and series-sibling awareness — so searching a series name surfaces its sequels.
  • Catalog deduplication automated in PL/pgSQL with normalized title/author matching, run via pg_cron with dry-run queries gating destructive merges.
  • OAuth 2.0 and JWT auth with row-level security policies, making shelves, ratings, and reviews private by default.

On iOS:

Native app built with React Native and Expo, sharing the web app's Supabase backend.
